# ADR-0006. 요구사항 해석과 범위 밖으로 둔 것

- 상태: 채택
- 관련: §7 "요구사항이 불분명하면 합리적인 가정을 세우고 ADR 에 기록"

## 해석한 요구사항

| 원문 | 해석 | 근거 |
|---|---|---|
| "등록한 HTML 을 바탕으로 캠페인과 **커스텀 신청 폼**을 만든다" | 커스텀 폼 = 캠페인에 템플릿을 연결하고 제목·완료 메시지·slug·공개 여부를 설정한 **배포 단위**. HTML 자체를 편집하는 기능은 없다 | §4 "범용 폼 빌더는 범위 밖". 편집기를 넣으면 곧 폼 빌더가 된다 |
| "인스타그램, X, 유튜브, 스레드용 배포 링크" | 채널을 enum 4종으로 고정. 채널마다 여러 링크(label) 허용 | 채널 추가는 enum + 접두어 상수 한 줄 |
| "신청 데이터는 DB 에 **CRM 명단**으로 저장" | `leads` 테이블 = 명단. 모든 필드 JSONB + 연락처 3종 컬럼 승격, 캠페인/폼/채널/시각으로 조회·페이지네이션 | 외부 CRM 연동은 §4 범위 밖 |
| "캠페인별 방문, 방문자, 신청, 전환율" | ADR-0004 의 정의 | |
| "인증한 운영자만" | 이메일+비밀번호 로그인, 운영자 계정은 시드로 생성(가입 없음). 운영자 간 데이터는 격리(다른 운영자 리소스는 404) | 조직/권한 관리는 요구되지 않음 |
| "API 를 문서화" | OpenAPI 3.1 (`docs/openapi.yaml`) + 관리자 앱 `/api-docs` Swagger UI | |
| "실제 AI 모델 연동은 범위 밖" | 운영자가 외부 AI 로 만든 `.html` 을 업로드하는 것으로 충족. 예시 파일 `examples/sample-ebook-form.html` 제공 | |

## 의도적으로 하지 않은 것

- HTML 편집기 / 드래그앤드롭 빌더 / 필드 스키마 정의 (폼 빌더 금지)
- 회원가입, 비밀번호 재설정, 다중 역할(role), 조직
- soft delete, 감사 로그, 실시간 대시보드, 기간 필터 (집계 쿼리에 `created_at` 인덱스는 준비됨)
- 파일 업로드 필드 제출 (ADR-0003)
- 봇 필터링, 레이트 리밋, CAPTCHA — 공개 제출 API 는 크기 제한(64KB, 필드 100개, 값 5000자)만 둔다
- CSV 내보내기, 문자/알림톡/광고 플랫폼 연동 (§4)

## 기본값으로 정한 것

- 캠페인은 생성 즉시 `ACTIVE` (만들고 바로 배포 링크를 뿌리는 흐름이 자연스럽다). `PAUSED`/`ARCHIVED` 로 바꾸면 공개 폼이 `410` 마감 안내를 보인다. `DRAFT` 는 스키마에 남겨 두었지만 UI 흐름에서 필수는 아니다.
- 폼 slug 는 자동 생성(`form-` + 8자)이며 운영자가 원하면 `[a-z0-9-]{3,60}` 로 직접 지정할 수 있다.
- 템플릿 파일 크기 상한 512KB, 완료 메시지 300자.
- 세션 7일. 방문자 쿠키 1년.
